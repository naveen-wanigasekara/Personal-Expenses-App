## Fixed findings

| Finding | Resulting behavior | Verification |
| --- | --- | --- |
| Reminder drafts were cleared before a save completed, with no protection against repeated submissions. | Pending writes lock the form and dismissal. Rejected saves retain the draft and show an error; retry clears the draft only on success. | Deferred/rejected save component tests and a MainApp failure/retry integration test. |
| Category add/edit forms closed before persistence completed and swallowed failures. | Both forms await persistence, retain rejected drafts, prevent duplicate pending writes, and allow retry. | Add/edit component rejection tests and a MainApp category retry test. |
| Chart forms closed before persistence completed. | Chart drafts and targets remain available after rejected saves, with a lock during pending requests. | Deferred/rejected chart tests and a MainApp chart retry test. |
| A custom chart and its dashboard placement were written separately. | Chart create/edit/delete writes chart definitions and dashboard layout together through one settings update and rolls both back on failure. | Assert one settings call, layout membership, failed-save rollback, successful reload, rename, and deletion. |
| Transaction-count charts displayed currency symbols. | Count metrics use unitless numbers in progress, donut, and line value displays. | Regression tests for all three chart types. |
| Deleting a card could remove debt from the overview while retaining associated transactions. | Cards with opening balances, transactions, installment history, or funded loans remain protected. Unused cards can still be deleted. | Purchase/debt preservation across remount, positive/negative opening balances, existing loan protection, and unused-card CRUD tests. |
| Reminder deletion lacked pending/error handling. | Deletion uses the form write lock and inline error handling. Saved rows remain visible until the server confirms deletion. | Rejected-delete/retry component test and existing reminder CRUD integration coverage. |
